# 全流程核查与下一步

当前功能流程可以贯通。会昌监测支持原值回放和原值离线基线实验，历史巡查支持病害检索；仍不支持正式风险预测。事实提取可继续修复；单位与含义齐备后才将原值实验扩展为物理位移或多变量预测，不扩大数据接入范围。整体条件见[整体能力与数据条件](整体能力与数据条件.md)。

## 目前各条流程的用途

| 流程 | 可以做什么 | 不能直接推导什么 |
| --- | --- | --- |
| PDF导入 → 基础解析 → 图谱/档案 → 筛查 → 离线报告 | 从来源页查询候选事实，安排P1—P4人工复核顺序 | 正式风险等级、失稳概率和发生时间 |
| 页面证据 → 原图/PDF追溯 | 核对抽取结果和候选边坡归属 | 图纸渲染图不是现场照片，归属候选不是已确认对应 |
| 会昌八表 → 观测库 → 日期回放 → 来源下载/离线报告 | 追查原值、零值、缺测和跳变，定位原始单元格 | 未核实单位和累计基准时，不计算物理速率或工程报警阈值 |
| 历史巡查 → 日期/对象/桩号/病害检索 → 原表追溯 | 查找2022年的边坡/桥梁病害原文 | 不代表近期状态，不按相近桩号自动绑定会昌 |

2026-10-13核查范围：9份PDF、62处候选边坡、410项当前页面证据、会昌8表40620条观测、88条历史巡查。没有导入其他县监测、770张PNG或其他新增报告。正式风险就绪数仍为0，164条候选规则尚未发布启用。

## 可重复运行的功能检查

使用已有`slopekg`环境：

```powershell
$env:PYTHONIOENCODING = 'utf-8'
python scripts/check_workflow.py --isolated
```

临时服务采用本机随机端口，检查后关闭，不监听PDF目录。检查读取现有成果，不重解析、不调用OCR或外部模型，不修改原始文件、人工修订或规则。检查已有服务时改用`--base-url http://127.0.0.1:8766`。

```powershell
python scripts/check_workflow.py --isolated --exports --output .private/reviews/本次流程核查.json
```

`--exports`明确开启三类报告的生成和下载核验，文件保存在`output/demo/share/`，采用独立名称，不覆盖既有报告。多次执行会留下不同测试报告。默认不开启导出。

检查覆盖PDF来源版本、图谱关系引用、档案/完整性/筛查对应、规则执行状态、图片目录与图谱、各类图片抽样下载、会昌八表全部原表下载校验、历史巡查分页及近期接口隔离、三类报告，以及检查期间输入是否发生变化。PDF上传和后台任务的失败/恢复路径仍由原有测试覆盖；本脚本不在真实资料目录上传测试PDF。

`passed`表示本项功能检查通过；`waiting`表示缺少该项输入或未开启导出；`failed`表示执行失败或结果矛盾。整体遇到`waiting`显示`partial`，遇到失败返回退出码1。完整的功能检查通过仍不代表事实语义准确、训练效果或工程风险验收。

## 下一步顺序与所需数据

1. **先改事实提取。** 使用已有六文件95项固定原页核对集，处理范围被拆成单值、材料/灾害体对象混淆和表格数字切断。新资料不加入固定答案集；修复前后用相同样本比较，并另留独立整报告验收。
2. **会昌先解释再计算。** 仅核实选中变量所需的单位、分量、累计/重置基准、时区及逐设备对应。现有零值、断档和跳变保留原样，不能擅自删除、填补或认定失效。
3. **先做原值基线，再按条件扩展。** 已用地表位移、裂缝两表比较保持值与7日变化，按时间先后和相同目标计分，不填补缺测。发布时间未知，仍不能当作真实在线验证。字段和基准齐备后再计算物理指标、引入水文变量；事件预测还需对应标签和独立验证。
4. **正式风险能力仍需另一组依据。** 取得已确认规则、带日期/工况的人工案例和独立验证用途后，才能评估风险判定或模型适配。监测数值和历史病害文字不能自行变成风险标签。

其它县数据只有在检验跨工点效果时才有用途，且需要先解决目录对应和倾角版本问题。PNG只有在图像识别或空间归档功能有明确需求，并取得位置/日期后才接入。资料是否新增不改变这些使用条件。
