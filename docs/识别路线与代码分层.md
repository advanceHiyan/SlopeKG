# 识别路线与代码分层

`DemoPipeline.run()`保留统一入口，通过`recognizer`选择路线；默认仍为`legacy`。basic、多模态、全文知识识别共享任务锁，分别管理业务编排和产物。旧文字deep已于2026-10-25删除，见[移除说明](旧文字deep移除说明.md)。新两路候选不自动写入旧图谱。

## 模块职责

| 层 | 模块 | 职责 |
|---|---|---|
| 入口 | `pipeline.py`、`recognition.py` | 兼容旧调用、选择路线；统一CLI/HTTP任务服务、模型配置与结果分页 |
| 旧路线 | `legacy_pipeline.py` | 本地basic/OCR解析、规则抽取、图谱发布与版本检查 |
| 模型传输 | `model_client.py`、`llm.py` | 统一兼容接口、密钥端点约束和错误回执；`llm.py`只保留规范规则抽取所需的文字接口适配 |
| 多模态编排 | `visual_pipeline.py` | 版面、模型语义切分、窗口细读、核验、查漏和恢复调度 |
| PDF输入 | `visual_document.py`、`visual_geometry.py` | 源文件身份、原生文字/已有OCR辅助、归一化几何、源PDF裁图与旋转 |
| 运行与预算 | `visual_runtime.py`、`visual_settings.py`、`visual_batching.py` | 缓存、回执、并发、调用/图片/文本预算、无损分批 |
| 事实与证据 | `visual_contract.py`、`visual_evidence.py`、`visual_sources.py` | 返回结构、数字/单位边界、对象编号、计量基准、实际来源及内容关联 |
| 核验 | `visual_review.py`、`visual_prompts.py` | 独立核验、准入状态和提示词；与HTTP及图谱发布解耦 |
| 任务与网页 | `jobs.py`、`server.py`、`web/recognition.js` | 后台进度、受限HTTP参数、候选查看；旧任务界面继续由`pdf-ingestion.js`维护 |

`pipeline.py`及`visual_pipeline.py`保留原公开辅助函数的兼容导出，供已有脚本调用；不能仅因模块内部没有调用就将其判为死代码。重复HTTP实现、重复校验分支和隐藏重复操作控件已移除。

## 多模态数据流

1. 从原PDF建立物理页清单和版面几何，由模型提出区域与章节延续关系。程序不按文件名、桩号或预设文档模板切分。
2. 按有限页窗口完成细读、核验和查漏，再处理后续窗口；窗口内先保证区域首次读取，不将全文件读数耗尽预算后才开始核验。
3. 默认增加一次独立复读：只给原图、目标框和页码，不给首次答案、OCR提示或候选字段。再由核验阶段结合原图与两次读取检查候选。复读不一致时保留待审；同一模型复读仍可能重复犯错。
4. 正文事实保留逐字引句；表格单元格和图中尺寸另行记录。单元格/尺寸必须明确关联事实，或说明仅作参考；“已经转录”不自动算“已完成事实提取”。未关联内容会使查漏保持未完成并进入有限恢复读取。
5. 代码校验数字、符号、复合单位、对象编号及单价的`unit_basis`（例如元/kg中的kg）；范围、对象关系和表格行列对应仍需模型核验。不同计量基准的冲突进入待审，不覆盖原值。
6. 跨页补充证据只来自模型明确声明的邻近延续区域和实际已读文字；图像按对应源页渲染。不能因数值相同就借用另一行或另一页的单位。

独立复读默认增加每个读取区域一次模型调用；密集表格、修复与重读还会增加调用。调用总量和并发仍受同一预算约束。预算不足、来源不明或字段不完整保留`partial`/`pending`，不会通过放宽校验制造成功率。`visual-v11`改变提示与准入规则，旧缓存不能代替新规则下的核验。

## 使用和扩展

### 第三路：全文知识识别（knowledge-v2）

独立入口 `/web/knowledge-recognition.html`，产物 `output/demo/knowledge-recognition/`。它借鉴 WeKnora 的对象目录、多对多证据归属、对象知识页，结合本项目的源文件哈希、页码/框/原文、值与单位检查、范围/角色/工况、核验和预算回执。它不调用 basic 的桩号、灾害词典、文件名或固定属性提取规则。

1. **全文发现**：保留 PDF 原生文字块和句界，按预算分块并重叠原文单元；遍历全部正文批次，逐步建立共享对象/概念目录。分正文主对象、目录线索和背景引用；目录线索在正文有实质内容后才提升，背景引用保存证据但不占主对象额度。身份上下文指父对象/业务作用域，不能把出现页码或章节位置当新身份。语义发生在对象识别和后续归属阶段，不把字符分块称为模型语义切分。
2. **跨分块归属**：再用完整目录遍历全部分块；一个对象可关联远处多个块，一个块可关联多个对象。保留具体原文单元，不靠距离决定归属。同名对象增加父对象/章节/时期上下文，共享简称本身不触发合并。
3. **知识重组**：先按对象收集非连续原文，再生成开放字段的事实及有谓词的关系。字段、值、单位、计量基准、整体/局部、角色、工况和时间分别保留。同一断言合并出处；不同范围或工况不合并。相同字段/范围/角色/工况/时间出现不同值时进入待审；这不是完整语义矛盾检测。
4. **证据检查**：原文引句必须来自所引单元；数值和单位必须出现在所引原文。核验另读源单元，检查主体、含义、范围和限定。模型通过仅为 `verified_model`，没有人工准确率含义。同一模型核验也可能重复犯错。
5. **完整性边界**：每块归属必须返回一次。预算耗尽、失败、遗漏保留待处理项。无足够文字的图形页列为未读，文本处理完成不能冒充127页全部读完。结果 API 检查源文件哈希及实现版本，陈旧结果不保留当前核验标记。

```powershell
python scripts/run_pipeline.py --recognizer knowledge --pdf "data/rawPDF/资料.pdf" --model-profile config/models/deepseek-knowledge.json --prepare-only
```

本地准备不调用 API、不读取密钥、不执行 OCR。确认资料可发送到所选接口后，去掉 `--prepare-only`。默认调用上限500、并发4；可用 `--knowledge-settings 本地JSON`调整预算，用 `--review-profile`指定另一个已获授权的核验模型。该路线当前读取原生文字，未实现扫描/图纸识别、跨文件自动同一化或知识问答检索。

同资料诊断脚本 `scripts/validate_knowledge_route.py` 先 `freeze` 保存检查点、源文件哈希和视觉页范围，再分别执行 `basic`、`knowledge`、`multimodal`。已知样本检查点属于内部诊断；多模态仅选页时，不报告全文件召回或相同成本的速度结论。非边坡单元测试仅验证机制与证据约束，不证明真实模型通用性。

网页在`/web/pdf-ingestion.html`选择资料目录中的文件和`config/models/*.json`中的命名配置。默认“本地准备”不执行模型或OCR；“启动多模态识别”需明确勾选向所选接口发送所选文件。上传PDF本身沿用旧路线，不自动启动付费多模态任务。

CLI示例：

```powershell
python scripts/run_pipeline.py --recognizer multimodal --pdf "data/rawPDF/资料.pdf" --model-profile config/models/deepseek.json --visual-settings config/visual-settings.json --prepare-only
```

确认资料可发送后，去掉`--prepare-only`运行正式识别。需要另一核验模型时增加`--review-profile config/models/qwen.json`；独立复读、核验与查漏使用核验模型，布局与首次读取使用主模型。兼容接口模型只需增加本地配置；不兼容接口通过实现`JsonVisionModel`协议接入，不能在PDF编排中加入厂商分支。

HTTP仅接受命名模型配置、目录内PDF以及调用上限/并发两个预算选项，不接受浏览器传入任意端点、密钥路径或失败重试策略。`credential_configured`仅表示配置了密钥引用，不保证账户余额、模型权限或接口可用。模型列表不读取密钥；密钥和完整调用回执不进入候选查询API。

`output/demo/recognition/`保存读取、核验、覆盖和候选；旧图谱产物路径保持不变。网页的“自动核验通过”对应`verified_model`，进度显示已观察到的页/区域/调用数，不能解释为人工复核比例。原始资料、复核记录和密钥均不随Git提交。

## 验证边界

离线回归使用合成PDF和替身模型验证调度、证据隔离、冲突、预算、任务锁、接口参数和前端交互。它能发现机制错误，不能证明真实文件的精确率或召回率提高。此次整理未继续付费模型调用，未改动人工答案或重建旧图谱。真实二率仍需按冻结的独立事实表，对新旧路线进行同口径整文件测试，待审和未处理项应保留在召回分母中。
