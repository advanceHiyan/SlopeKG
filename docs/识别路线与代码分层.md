# 识别路线与代码分层

## 当前开发状态（2026-11-11）

知联 Knowledge（`knowledge`）和多模态视读 Visual（`visual`，兼容名 `multimodal`）**暂时归档，非必要不继续开发**。现有代码、手动入口、产物和历史说明保留。默认不新增功能、优化算法、调整提示词或参数，不主动运行模型回归，也不补跑本轮未完成实测或继续生成专项调试报告。

后续开发重点为智能识别、整读 Document、基读 Basic 及边坡资料库。用户明确要求恢复，或在用路线、历史读取和数据安全确有必要兼容修复时，先说明必要性并限制改动范围。共享模块变更不自动触发这两路专项开发或实发模型验证。下文相关章节作为历史技术记录保留。

## 2026-11-03 实验第四路：整读 Document

独立编排为 `document_pipeline.py`，不调用知联的对象发现与归属流程。`document_prompts.py` 保存完整提示词；`document_contract.py` 核查重建、分组、引文、单位、复核与去重；`document_workflow.py` 处理来源链接修复、复核投影和跨组检查；`document_settings.py` 管理容量；`document_service.py` 对接CLI/HTTP，`document_render.py` 输出逐阶段报告。共享已有模型传输、PDF渲染、坐标来源和任务锁。

1. 每次读取相邻原页图像与原生坐标文字，恢复完整段落、表格和阅读顺序。容量窗口不定义对象边界，跨页段落以可审核的链接连接，尚未拼成一个可替代原件的巨型字符串。未重建原生文字保留，模型建议排除的页眉页脚也保留原文供复核。
2. 结构存在缺口时，先尝试有唯一几何覆盖及逐字依据的本地链接修复；不满足条件的保留原文。默认最多追加一次原页重建。随后在全部恢复内容上形成对象、共享与未定资料组；同一完整表格可以属于多个组，资料组可跨非连续页。未覆盖的正文自动进入未定组。取消固定的单独分区审核请求，保留全文分区这一步。
3. 按资料组安排提取及紧随其后的原页复核，共享来源在同一请求中只发送一次。提取规划默认20000字符，为后续候选留容量；超容量按完整内容块分批，不按固定字符截断。原页复核实际超限时再分候选，保留完整组上下文。给复核预留至少一次请求额度，失败批次不抹掉已完成批次。非法候选逐条隔离，保留原回包和原因。
4. 原页复核可补引文、更正主体、父对象、范围和角色，修改前记录保留。更正重新通过相同来源/值/单位检查，更正的主体还须有逐字依据，不能靠审核意见升级。复核新增事实仍待核。子对象保存显式父对象及证据；同名子对象不跨不同父对象/资料组自动合并。计算值与要求值使用不同角色。
5. 最后仅传紧凑事实索引作一次跨组检查，不再重复发送全部正文、坐标和候选证据。此检查只能指出问题并降为待核，不能提升可信状态。`workflow_complete`单独记录预定阶段是否执行完成；有未解来源、归属或事实问题时，文档仍可为`partial`。

默认相邻页窗口2、页面长边2200、调用上限24、完整提示词容量100000字符、提取规划20000字符、结构修复最多1次、每次最多6张图。文本分区和跨组索引检查不受6页图片上限限制。模型最大输出沿用配置与供应商能力校核，不能用调用上限替代输出完整性校验。当前编排串行；`model_concurrency`是传输上限，不代表已经并行。

**目前边界：**全文分区和最终紧凑索引仍分别必须能放入一次文本请求，尚未实现长文档分层规划。单一完整内容块超限会明确失败；整体预算可能不足以执行所有资料组，待处理项必须保留。未做跨文档实体统一，也未连接现有知联/视读的历史快照和评估衔接。`source_aligned`是原生文本及同模型复核支持；`model_supported`含视觉转录，不是独立确认。局部真实选页与合成样例均不能推出整份报告准确率。

## 知联 v3.6.1：保留分块事实与来源覆盖

知联在跨块归属的同一次阅读中提取开放字段的原子事实，随后按对象重组。分块事实先独立通过来源、单位和归属校验；重组遗漏或失败不会删除这些候选，也不会赋予独立审核标记。错误归属及未知来源按项隔离，仍保留未解决项。

表格多层表头按原始行结构与数据行关联，单位仍校核到数值所在列。全角数字/拉丁字符只作排版等价比较，引文保留原字符；不折叠公式的上标、下标和量纲。基读、视读算法保持本轮开始时版本。机制检查和真实固定资料回归分别记录；隐藏资料只在最终冻结后统一评分。

对象发现可返回附原文引证的文档用途候选，连同对象说明传给归属和重组；不给文件名配置角色规则。用途候选只提供业务背景，数据角色仍须依局部原文判断；unit_basis仅表示计量分母，不表示来源位置。

发现阶段将某栏目列为support/catalog，不等于允许丢弃正文。存在未覆盖的编号栏目时，知联最多追加一个原文批次恢复其中的实质对象/属性，复用已完成阶段；仍受同一总调用上限约束。原始来源、恢复出的候选、未处理片段及失败均分别保留，标题或裸数字不会直接转成事实。

输入中的“现状/设计/引用”等明确中文角色与既有英文枚举等价处理，保存原标签；“要求/方法/署名”等含义不唯一的标签仍待审，不按关键词推断角色。

## 2026-10-31 流程复核与局部改造

- 知联 `knowledge-v3.2` 的发现、归属和重组输入保留来源框及OCR置信度。标题区OCR完成不代表页面正文完成；原生文本不足的图像/图纸页规划全页OCR，执行仍受明确的 `ocr_pages` 上限约束。多次OCR重叠只去除同文同位置的重复，不把不同位置的相同数字合并。
- `source_accounting` 显式保留未归属来源及整页无对象归属的缺口，不因发现/归属请求返回成功就声称这页已经整理完。不会把孤立数字强配给附近对象；图形测量仍需视读及原图语义核验。
- 视读 `visual-v13` 在读取前按剩余调用预算规划读取、独立复读、核验和查漏。区域过细而最小周期放不下时，合并同页来源范围并保留原始区域及对象线索，不合并实体身份；周期仍放不下时明确保留未处理状态。该预算估计不是全文成本承诺，密集内容仍会按文本容量分片。
- 同一源图共享核验按实际文本容量分批，取消每12条候选的二次硬拆分；异图裁剪和输入容量边界继续保留。尺寸转录须进一步说明被测对象、量义及图中测量依据，才能作为完整测量事实；读到数值只算来源转录。
- 非法JSON回执保留内容类型、长度、哈希、解析错误位置；不把原文、推理内容或秘密写进异常/回执。历史未保存的响应无法据此恢复。
- 本轮只做匿名离线机制测试及旧缓存诊断，没有新增模型预测；真实语义质量尚待新的冻结实测。历史预测、用量和评测结果不回写。

## 2026-10-31 通用修复与请求上限

- 知联 `knowledge-v3.1` 对批量回复逐对象验收。额外、缺失、重复或结构无效的对象隔离保存，其他合格对象继续处理；异常事实也不拖掉同对象的其他事实。提示词只澄清 `subjects` 是输出对象、`registry` 供关系引用，不加入特定文档、字段或答案。
- 共享解析器统一原生文本到显示页面坐标，记录旋转矩阵与几何版本。旧原生缓存自动重解析，字节匹配的OCR继续复用；OCR原生坐标经相同旋转转换后归一化。越界框保留问题状态，不能仅凭字面匹配获得通过。
- `model_limits.py` 统一已配置模型的最大输出：DeepSeek为393216，Qwen3.8-Max为131072；Kimi K3先用官方计数接口估算当前输入，再将 `max_completion_tokens` 设为1048576减去输入token数。输出上限与总请求数分别管理，调用方的较小临时值不能覆盖已核定模型上限。
- `finish_reason=length` 是有回执的截断，保留用量并停止该模型后续发送，不自动重发或伪称状态不明。请求超时、鉴权、余额和明确临时错误仍按各自边界处理。
- 基读上层仍是有限的行业目录、章节和字段规则基线，缺少通用对象发现能力；不继续为单份自由文本补规则。其PDF、表格和OCR组件继续供其他路线复用。

上限依据：[DeepSeek](https://api-docs.deepseek.com/api/create-chat-completion/)、[Qwen3.8-Max](https://help.aliyun.com/zh/model-studio/qwen3-8-max)、[Kimi](https://www.kimi.com/help/kimi-api/api-troubleshooting)。配置和离线检查不等于所有供应商均已真实调用。

## 视读 Visual 数据流

1. 从原PDF建立物理页清单和版面几何，由模型提出区域与章节延续关系。程序不按文件名、桩号或预设文档模板切分。
2. 按有限页窗口完成细读、核验和查漏，再处理后续窗口；窗口内先保证区域首次读取，不将全文件读数耗尽预算后才开始核验。
3. 默认增加一次独立复读：只给原图、目标框和页码，不给首次答案、OCR提示或候选字段。再由核验阶段结合原图与两次读取检查候选。复读不一致时保留待审；同一模型复读仍可能重复犯错。
4. 正文事实保留逐字引句；表格单元格和图中尺寸另行记录。单元格/尺寸必须明确关联事实，或说明仅作参考；“已经转录”不自动算“已完成事实提取”。未关联内容会使查漏保持未完成并进入有限恢复读取。
5. 代码校验数字、符号、复合单位、对象编号及单价的`unit_basis`（例如元/kg中的kg）；范围、对象关系和表格行列对应仍需模型核验。不同计量基准的冲突进入待审，不覆盖原值。
6. 跨页补充证据只来自模型明确声明的邻近延续区域和实际已读文字；图像按对应源页渲染。不能因数值相同就借用另一行或另一页的单位。

独立复读默认增加每个读取区域一次模型调用；密集表格、修复与重读还会增加调用。调用总量和并发仍受同一预算约束。预算不足、来源不明或字段不完整保留`partial`/`pending`，不会通过放宽校验制造成功率。`visual-v11`改变提示与准入规则，旧缓存不能代替新规则下的核验。

## 使用和扩展

### 知联 Knowledge（knowledge-v3）

独立入口 `/web/knowledge-recognition.html`，产物 `output/demo/knowledge-recognition/`。v3借鉴WeKnora的对象目录、非连续证据聚合和对象档案，复用基读的解析、表格和OCR能力。它不调用基读的桩号、灾害词典或固定工程字段提取器，不按文件名识别对象。

1. **统一证据**：原件SHA-256一致且完整的基读解析可复用；否则调用`PdfParser.parse(generic=True)`，不按文件名选择行业语义，逐页检测原生表格。表格按真实单元格序列化为行，保留表头与数据行的关联；不填充空单元格。重复原生文字只在框内且文本确实重复时抑制。已完成且任务/原件哈希一致的OCR文字可复用；未映射的图片像素框不冒充PDF坐标。
2. **全文发现**：遍历全部可用文字/表格/OCR批次，维护共享对象目录；区分正文对象、目录线索和背景引用。身份上下文是父对象或业务范围；共享简称不自动合并对象。原文分块是按源块和句界的本地处理，不称为模型语义切分。
3. **跨块归属**：完整目录再次扫描全部分块，保留多对多span归属。数据行携带真实表头，唯一明确名称和章节只补充证据选择线索，不转成模型已验证事实。逐条引文检查异对象章节和表格行归属；额外引文污染也不能随正确数值通过。
4. **知识重组**：先聚齐每个对象的非连续原文，再将共享证据的多个对象合批整理，最多6对象一批，原文只传一份；大对象按证据预算分段，保留每段状态。档案列出事实、子对象和共享主题。具体作用域与源行一致时，可把主题下的具体案例候选放回具体对象，但不继承核验标记；主题保留链接。
5. **减少复核**：本地引文/数值/单位/主体检查失败的条目直接待审，不再花API修复本地问题。默认`review_mode=selective`，普通原文对齐记录标记`source_aligned`，不是`verified_model`；仅歧义或关系候选进入可选模型复核，默认最多4批。复核批按上下文预算合并，最多64条，取消每12条必复核及自动追加归属模型复核。不同范围、工况、时间的事实不合并；同范围不同值保持待审。
6. **预算和历史**：默认总调用硬上限64、并发6，不自动提额。准备阶段列出发现/归属批次，目录建立后补充重组调用计划。缓存键包含`knowledge-v3`和完整提示词。旧版本运行记录先归档到`history/`，旧缓存不改写、不当成新版本预测。已明确返回429/500/502/503的请求可指数退避重试，每请求最多2次、全程最多4次额外尝试，重试也占总调用上限；共享接口冷却时间。服务器要求等待超过30秒则停止短重试。鉴权/余额错误、超时、HTTP408/504、JSON/合同错误及旧started记录不自动重发。
7. **边界**：逐块与逐对象返回完整性分别检查，失败、遗漏、超额保留partial。OCR文字不代表曲线、图例、工程图尺寸已理解；图形待读与OCR待处理页分列。结果API检查原件与代码版本；原文对齐、模型支持、人工核准不能混为一谈。

```powershell
python scripts/run_pipeline.py --recognizer knowledge --pdf "data/rawPDF/资料.pdf" --model-profile config/models/deepseek-knowledge.json --prepare-only
```

本地准备只做解析和缓存复用，不调用API、不读取密钥、不启动新OCR。`ocr_pages`默认0；明确设置正数后，正式运行才通过基读`OcrRunner`做有页数上限的本地OCR，新结果缓存在知联的`source-cache/`，不覆盖基读结果。需事先具备可用的本地OCR环境；本次改造未安装环境或运行真实OCR模型。JSON参数可通过`--knowledge-settings`传入，例如`{"max_calls":64,"max_review_calls":4,"ocr_pages":0}`。`review_mode=all`仅为显式全面复核模式，仍受预算约束。真实模型发送须另有当前授权；此前暂停API的指令不因代码默认值而失效。

定向实测可用`scripts/smoke_knowledge_selected.py --pdf 原件 --pages 物理页列表 --output 独立目录`先冻结范围、代码、完整提示词和预算；加`--execute`只执行一次。选页内容仍保留原始物理页码，未选页不进入模型输入，也不计作整份文档完成。

`knowledge_composition.py`负责对象证据包、共享证据合批、主体门控和档案派生；`knowledge_document.py`负责基读证据适配。`tests/test_knowledge_v3.py`用匿名设备、档案、真实绘制表格和模拟OCR验证机制，不能证明真实模型的通用性或整份资料准确率提高。

知联 `knowledge-v3.7` 的请求容量由 `knowledge_batching.py` 统一计量：系统提示、阶段提示、对象目录、表头、单元格、坐标及 JSON 转义全部按实际发送格式计算。发现和归属按完整容量装包，过大单块可继续按原始来源单元拆分，每段保留所需表头；发现目录每次增长后重新计量。重组和复核也检查完整请求。查漏仍最多一批，放不下的来源明确保留在 `remaining_source_ids`，不自动追加请求。不可再分的来源或目录超限时明确失败并保留来源。输入容量与模型最大输出 token、请求次数上限分开控制。

知联 `knowledge-v3.8` 进一步处理目录本身膨胀：目录及对象导航资料超过输入容量的三分之一时，`knowledge_directory.py` 改用保留全部对象ID、名称、类型、别名、父级范围和来源页的身份索引，长描述、重复定位与用途证明仍完整保存在文档记录中。发现、归属、重组、查漏和复核共用这一策略，原文与表头不裁剪，对象身份字符串不截断，不按排序丢掉末尾对象。身份索引本身或不可再分的原文仍超过输入容量时明确保留失败；该机制不能代替真实模型的识别质量验证。

同资料诊断脚本 `scripts/validate_knowledge_route.py` 先 `freeze` 保存检查点、源文件哈希和视觉页范围，再分别执行 `basic`、`knowledge`、`multimodal`。已知样本检查点属于内部诊断；多模态仅选页时，不报告全文件召回或相同成本的速度结论。非边坡单元测试仅验证机制与证据约束，不证明真实模型通用性。

网页在`/web/pdf-ingestion.html`选择资料目录中的文件和`config/models/*.json`中的命名配置。默认“本地准备”不执行模型或OCR；“启动视读 Visual”需明确勾选向所选接口发送所选文件。上传PDF本身沿用旧路线，不自动启动付费多模态任务。

HTTP仅接受命名模型配置、目录内PDF以及调用上限/并发两个预算选项，不接受浏览器传入任意端点、密钥路径或失败重试策略。`credential_configured`仅表示配置了密钥引用，不保证账户余额、模型权限或接口可用。模型列表不读取密钥；密钥和完整调用回执不进入候选查询API。

`output/demo/recognition/`保存读取、核验、覆盖和候选；旧图谱产物路径保持不变。网页的“自动核验通过”对应`verified_model`，进度显示已观察到的页/区域/调用数，不能解释为人工复核比例。原始资料、复核记录和密钥均不随Git提交。

## 验证边界

离线回归使用合成PDF和替身模型验证调度、证据隔离、冲突、预算、任务锁、接口参数和前端交互。它能发现机制错误，不能证明真实文件的精确率或召回率提高。此次整理未继续付费模型调用，未改动人工答案或重建旧图谱。真实二率仍需按冻结的独立事实表，对新旧路线进行同口径整文件测试，待审和未处理项应保留在召回分母中。
