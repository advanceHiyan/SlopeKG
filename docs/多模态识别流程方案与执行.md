## 调研依据与取舍

| 一手资料 | 借鉴内容 | 本项目的取舍 |
|---|---|---|
| [MinerU2.5论文](https://arxiv.org/abs/2509.22186)、[MinerU开源项目](https://github.com/opendatalab/MinerU) | 全局版面分析与高分辨率局部识别分开，降低整页高分辨率处理开销 | 原页概览→模型给出区域→从原PDF渲染局部，不放大旧缩略图；不安装整套MinerU |
| [PaddleOCR-VL-1.5论文](https://arxiv.org/abs/2601.21957)、[PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR) | 文字、表格、公式和图表是不同识别维度，真实扫描畸变也影响效果 | OCR保留为可插拔的辅助证据；已有OCR须匹配当前源文件，不能当作标准答案；本轮不增加本地模型依赖 |
| [Docling](https://github.com/docling-project/docling) | 统一文档表示，保留版面、阅读顺序、表格结构，同时支持OCR与VLM | 无论扫描页、原生文字页、纯矢量页，使用同一图像路线；输出统一的页、区域、表格、事实、证据和状态 |
| [olmOCR 2论文](https://arxiv.org/abs/2510.19817) | 用可检查的阅读行为约束识别质量 | 用确定性的坐标、来源、引句、预算和状态检查配合模型核验；不声称复现其训练方法 |
| [OmniDocBench论文](https://arxiv.org/abs/2412.07626)、[评测代码](https://github.com/opendatalab/OmniDocBench) | 分开评价文字、表格、公式与阅读顺序，不能用单个总分代替各项质量 | 日后同时测文字误差、单位/表格结构、对象归属、整对象覆盖、端到端二率；公开榜单分数不能直接等同于施工图事实准确率 |

这些资料支持技术路线，不构成本项目达到人工水平的证据。大模型自检可能重复同一种错误；同模型重复通过不是真值。对未见整文件的盲测仍是必要验收。

## 开工前的六项承诺

1. **P1 统一输入**：所有PDF从原页渲染，保留物理页码、源文件SHA256、页面坐标；原生文字和已有OCR为可选辅助。不按文件名、道路或固定坐标选工作流。
2. **P2 模型切分**：逐页版面发现→有重叠上下文的页卡窗口→模型分配章节/对象与延续关系。程序检查每个区域被分配且只分配一次，不按桩号正则切文档；归属不清保留未决。
3. **P3 细读与重读**：有限图像/文字预算内读取区域，保留原文、表头、空单元格、跨行跨列、尺寸和单位；由模型提出归一化区域与旋转角度，程序从原PDF重渲染。预算耗尽须保留未处理记录。
4. **P4 核验和查漏**：事实保留对象、属性、值、单位、限定词、范围、角色、条件、时间和引句；另轮模型核验，原页查漏并补读；支持、待核验、拒绝分开，来源冲突保留。覆盖检查不冒充召回率。
5. **P5 通用模型接口**：业务调用JSON/图像协议，端点、模型、思考参数、token参数差异和图像选项由profile控制。显式项目密钥来源、绑定端点、不重定向、不回退其它账户；串行调用、调用预算、缓存、续跑、失败留痕。
6. **P6 旧路兼容及验收**：增加legacy/multimodal选择，旧basic/deep主体保留；新输出独立；离线契约与合成PDF测试覆盖正常/漏读恢复/预算/中断/冲突，回归旧功能。不运行新付费评测。

## 数据流与准确率策略

`原PDF → 逐页概览 → 模型区域/阅读顺序 → 窗口式语义切分 → 区域原图细读 → 疑点原图放大/旋转 → 独立调用核验 → 全页查漏/补读 → 带出处的事实与待办`

窗口只带当前页卡、相邻边界和已解析的边界归属，不带不断增长的聊天历史。每页始终保留读取状态；版面失败时通用回退为全页未决区域，不调用旧的固定栏规则。单个结构化单元超预算、区域过多、重读次数不足、模型失败或返回截断，均明确partial/failed；不裁掉尾部后报成功。

核验包括对象、属性含义、值、单位、范围、角色、限定、条件和时间。数值、单位和限定词都必须在原文及另轮核验的引句中对齐；匹配检查数字和单位的边界，不能让4.5凭4.51的子串、m凭m²的子串通过。单位上标不作会混淆m²/m³的兼容归一化。核验图从原PDF以更高目标分辨率渲染，减少重复相信同一张缩略图的问题。只有所有检查通过才标`verified_model`，不叫人工确认。未知对象/角色/范围仍待核验。相同事实去重但保留每次读取和核验；不同范围/工况不直接合并，冲突值不自动择优。

OCR本轮复用已有成果，不重新启动Paddle推理。只有文档、OCR任务、OCR记录的源文件哈希都一致才可用；旧图像像素坐标不冒充页坐标。无OCR不阻断视觉路线。辅助文字过长时不挤占原图，明确标记未送入提示词，完整原始辅助记录仍在本地结果。未来可通过同一辅助证据回调接入新OCR或专用文档解析器，业务编排不依赖某个OCR包。

## 运行入口

原命令保持原行为，默认`--recognizer legacy`，其下的`--mode basic/deep`仍有效。新路线显式给出PDF，避免一次误发送整个资料目录：

```powershell
# 只准备本地清单，不读取密钥、不运行OCR、不调用模型。
python scripts/run_pipeline.py --recognizer multimodal --pdf "D:/资料/任意文件.pdf" --model-profile config/models/deepseek.json --prepare-only

# 实际运行（本轮未执行此命令）：所有物理页均进入流程。
python scripts/run_pipeline.py --recognizer multimodal --pdf "D:/资料/任意文件.pdf" --model-profile config/models/deepseek.json --visual-settings config/visual-settings.json
```

`--pdf`可重复。模型切换只换profile；三个示例保留各自思考/图像/token参数差异，使用现有项目`.secrets`文件，不含密钥。可额外传`--review-profile config/models/kimi.json`，将事实核验和查漏交给另一个模型，降低同模型错误相关性；也不据此保证正确。默认串行，适配并发额度为1的账户。新服务可实现`JsonVisionModel`，无需伪装成同一个厂商；兼容接口可直接配置。没有假定所有模型支持相同的思考参数。

`--prepare-only`同时输出按每页一个区域估算的调用数量，方便调整整次运行的预算。渲染边长、每图像素上限、整次输入图像素总量均可配置；这些数值是资源预算，不是版面分界坐标。新路线不接受旧的`--no-llm`开关，避免“以为关闭模型却仍调用”的歧义。

输出到`output/demo/recognition/`，不改basic/deep图谱或活跃指针：

- `run.json`：配置、模型身份、运行状态、请求回执、缓存命中、待核验计数；precision/recall保持null。
- `documents/*.json`：全部物理页、模型切分、每次原文读取/表格/尺寸、核验、疑点、查漏和源哈希。
- `facts.jsonl`、`verified_facts.jsonl`、`review_queue.jsonl`：全部去重事实、模型核验通过事实、其余候选。
- `coverage.json`：每页完成/未决/失败与查漏结果。
- `images/`、`cache/`：原PDF渲染图和带内容身份的成功/失败请求记录。缓存身份包括模型配置、提示词、源哈希及实际图像内容；改变输入不会复用旧答案。

失败或中断的调用不自动重试，避免未知计费状态下重复收费；明确需要重试时，在本地settings中设置`retry_failed:true`，历史尝试仍保留。HTTP 429也不会一轮疯狂重发。所有预算可配置，默认调用上限200不表示足够跑完任意PDF，耗尽会明确未完成。

## 2026-10-17：真实调用暴露的问题及通用修复

使用项目专属DeepSeek账户，开启thinking与max reasoning、131072输出token上限；没有将人工核对答案作为识别输入。实验代码、协议快照、请求回执、原图与人工核对留在本地`.private/reviews/20261016_visual_live/`。选物理页仅用于本轮开发测试，正式入口默认仍处理全部物理页，章节/对象切分由模型决定。

| 原计划 | 实跑发现 | 本次代码修复 |
|---|---|---|
| P1 所有PDF统一表示 | 移除PDF旋转元数据会使正常横页侧置，文字框与渲染框可能不一致 | 保留显示方向，文字框用旋转矩阵映射至同一归一化页坐标；图像按源哈希及渲染参数缓存、原子写入 |
| P2 全局布局与语义切分 | 模型估计框会截掉标题、句尾；剪碎后主语丢失；同一张表的表头、单位、数据被拆开 | 模型负责语义分组，程序依据它引用的原PDF几何锚点生成裁图；同表优先整体读取，明确共享`table_id`的碎片由程序合并，不合并不同表；无锚点时仍使用模型框；唯一逐字引句可对齐源文字框，但不据此改写内容 |
| P3 原图细读/重读 | 仅将整图渲染得更大，不能保证服务端实际看到更清楚的小字 | 核验补充从原PDF生成的逐事实局部图，预算内给定位页、正文区域与证据局部图分别留空间；越界证据保留待审并扩框重读，不再整批丢弃；扩框动作本身不撤销其它已独立核验的区域内事实，真实语义疑点仍待审 |
| P4 可追溯核验 | 单句必须同时包含数值、单位和表注的假设会误拦表格；一个null布尔字段曾使整批复核作废；同名“该边坡”可能跨章节误合并 | 支持多片段逐字证据，独立核验行列/对象关系，每片证据仍须存在于转录；9项核验缺一不可，单项格式错误只隔离该候选；去重/冲突考虑模型确认的章节延续作用域 |
| P4 整页查漏 | 一个大表读数作为单个审计单元超过上下文预算，导致整页无法查漏 | 审计按连续转录片段、带行列定位的单元格、尺寸和事实无损分片，不裁掉尾部；明确其它分片缺席不等于内容缺失 |
| P5 通用模型调用 | 串行适配会浪费可用并发；重复并发请求可能重复收费或超预算；共享同一证据图的事实逐条核验成本高 | 新增`model_concurrency`，本次实跑上限4；只将HTTP/缓存处理放入线程，PDF渲染留在事件循环线程；调用额度原子预留，同一缓存身份加锁；核验按不同证据图数量与文字预算分批；读数落盘后再核验，逐批保存状态；未知计费状态不自动重试 |
| P6 兼容旧路线 | 新流程需要独立验证，不能用模型自检数冒充人工二率 | 旧basic/deep默认行为与正式图谱入口保持原状；真实识别、自动准入、人工判定分开保存，开发样本不充当总体盲测 |

[DeepSeek视觉文档](https://api-docs.deepseek.com/guides/vision/)说明大图会缩放至约1300×1300面积量级。因此关键是原图局部裁切与可靠定位，不能把`detail:original`或更大PNG等同于服务端读取了全部原始像素。并发需按账户额度配置，见[官方限流说明](https://api-docs.deepseek.com/quick_start/rate_limit/)。这些修复遵循原调研中的全局布局、局部识别、统一证据表示与分层验收方向，没有复现或声称达到论文模型的指标。

实际人工检查也发现：模型可能把引用公告年份当成事实时间，或在结构化字段中遗漏原文的主次限定。提示词补充通用时间关系与限定保真核验，新增prediction/simulation角色；不能因为数值正确或同模型多次通过就接纳整条事实。针对已发现问题的复核只作为定向回归，不能证明对未见文件的泛化。

实跑又暴露两种证据检查错误，并已通用修复：复核引用同页先前已读的表名时，不能因为它不在当前区域转录中就整条拒绝；补充引句现在须绑定到同页真实已读区域，主断言仍须来自当前区域。表格Markdown分隔符、全半角标点按词元校对，保留数值、负号、单位上标与复合单位边界，不能让`1 | 2`支持`12`、`4.51`支持`4.5`、`m²`支持`m`。可选字段核验也须区分“不适用”和“有误”：候选与原文均无时间约束时应通过时间项；非空候选错绑公告年份仍不能通过。没有把模型返回的false直接改成true，而是明确提示词语义后重跑受影响的核验。

利用真实回包的离线重放单独记录，客户端禁止网络，不读取密钥、不产生新费用；它仅用于检查确定性后处理，不能算独立模型测试。重新核验只发送必要的新提示词批次，复用已有布局和原文读取缓存。

对表格引句中的明确省略，只允许在同一原文行内按原顺序对齐，不允许跨行拼接另一个对象的数字，也不接受不存在的解释性括号。原始引句保留，不把规范化后的内容回写为识别答案。

离线流程检查从26项扩展到40项；全套后端/已有语料370项、浏览器36项通过。新增检查包括真实并发上限、并发预算、防止PDF跨线程、原页选取、源几何锚点、单条复核异常隔离、分散表格证据、大表审计不丢尾部、同表分组合并、共享证据批处理、扩框不误撤其它事实、跨区域引句可追溯和数字/单位边界保真。离线假模型只验证编排与契约，不用于计算内容二率。

仍需完成独立整文件盲测、无原生文字页的可靠几何辅助、跨页证据绑定与调用效率验收。第一轮实跑包含预算耗尽和进程中断；未完成记录必须留在覆盖与召回分母中，不能将它们排除后宣称达到人工水平。完整实验数字与逐点证据以本地人工复核记录为准。

后续应先细分不确定性的影响范围，区分版面结构疑点与某条事实的数值/单位/对象疑点，再按证据依赖决定放大内容与顺序，避免重复读无关小片。数值一致性可由模型给出明确单元格引用，程序以精确算术校核并标记来源冲突，不能擅自改原表。解决这些通用问题后，再冻结协议做整文件盲测与旧200项同口径对照；不能靠提高预算或排除待审项制造召回率提升。
