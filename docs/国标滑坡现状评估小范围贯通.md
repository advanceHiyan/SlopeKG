试点已执行的规则为：

- 表4稳定系数列比较。对同一断面/工况的 Fs、Fst 配对；Fs≤1时不强求Fst。系数列不会自动产生滑坡发育程度。
- 表15。先分灾情、险情；一项有效指标即可继续。区间跨界、多项指标或同指标来源冲突保留分支，不补零、不静默取最高。
- 表17九格查表。已有适用发育/危害结论可以直接查表；条件输入的结果继续标为条件结果，实际人工复核状态单独记录。
- 明确单位转换。例如原文裂缝宽10–20cm转成0.1–0.2m，保留约值、共述范围和原值。

规则和定性原文单独保存在 `data/standards/GBT40112-2021/landslide_current.review.json`。这是对照原件的规则稿，尚无工程专家签认。已融入表4/5原文、表15/17明确判定、表16诱因分类及15条范围/调查/现状评估条款。定性综合判断由同一流程中的模型步骤提出有据建议或弃答，不补造布尔判据；稳定求解器未接入。

2026-10-31后续实现增加 `run`、`retrieve`、`judge`、`assertion`；仍只有一套评估流程。模型复用项目 `config/models/deepseek-knowledge.json`，输出预算4096 tokens、90秒超时，单次请求，失败保留部分计算。请求、模型身份、原文引用、使用回执与规则快照入库。引用ID和引句必须匹配给定证据，模型建议保留 `conditional` 和待人工复核。相同请求成功结果复用；失败请求可显式重试。模型输入中的省略事实ID单列，不声称整份资料判断完整。

## 接口

现有服务增加下列接口。原 `/api/risk/assess` 的P1–P4筛查含义不变。

| 方法和路径 | 输入 | 返回 |
| --- | --- | --- |
| GET `/api/standard-assessment/contract` | 无 | 已实现子集及未实现能力 |
| GET `/api/standard-assessment/targets` | 无 | 现有边坡与本流程适用性提示 |
| POST `/api/standard-assessment/run` | 版本、目标或案例、可选时期及 `use_model` | 自动检索、采用或建议、查表的一份结果 |
| POST `/api/standard-assessment/retrieve` | 案例及预期版本 | 关联原件可读文字中的危害/等级关键词命中；对象时期未核的保留候选 |
| POST `/api/standard-assessment/judge` | 案例及预期版本 | 同一配置模型的有据发育建议或弃答，持久化使用回执 |
| POST `/api/standard-assessment/assertion` | 单项值、实际操作者、依据、可选案例原文引用 | 新来源记录与断言；增加版本并需重算 |
| POST `/api/standard-assessment/prepare` | 契约版本、现有目标对象、任务；可选来源已有时期选择 | 案例及现有事实；不要求用户填写全部22类变量 |
| POST `/api/standard-assessment/context` | 契约版本、案例ID、事实ID列表 | 原句/表头/工况/位置/原文检查状态、表4/5上下文 |
| POST `/api/standard-assessment/evaluate` | 契约版本、案例ID、预期选择版本 | 部分结果、表17结果、推导链、缺失及冲突 |
| POST `/api/standard-assessment/review` | 契约版本、案例ID、预期版本、目标事实、纠正或分支选择、操作者、理由及已有证据 | 追加记录、替代事实、递增版本；旧记录保留 |
| GET `/api/standard-assessment/case?case_id=...` | 案例ID | 持久化事实、各版结果及是否当前版本 |

请求的最小例子：

```json
{
  "contract_version": "slopekg.standard-assessment/0.3.0-review",
  "target_ref": "G351-AUTO-038",
  "task": "landslide_current"
}
```

`evaluate` 还需要 `case_id` 和整数 `expected_resolution_version`。纠正后旧版本请求返回409。修改来源断言会新增事实，未变的推导按原输入ID和方法/规则快照复用；旧结果保留为历史。

纠正接口支持 `actor_kind=human|assistant`，必须填写实际操作者。代理按原件修正引用不变成人工专业签认。新增 `clear_selection`、`accept_fact`、`confirm_result`；后两项仅接受实际人工操作，并保留操作者、依据、目标版本和旧结果。最终确认须已有唯一格值、无阻断冲突且复核环境/诱因及范围；资料或规则变化后旧确认失效。单项新手工输入经 `assertion` 注册来源，代理输入还必须有原句支持。当前声明口径依赖实际操作者如实填报，不声称完成身份资质认证。

RV-026已修复：同一指标显式选择来源后，表15只使用生效来源，其他来源保留；撤销后重新暴露冲突。不同指标跨级的专业口径仍按RV-002保留分支，没有静默取高。

数据库业务记录分别为 `assessment_case`、`fact_assertion`、`derivation_run`、`case_resolution`、`assessment_result`、`review_decision`，另保存对象绑定、证据上下文及不可变原记录。当前SQLite的每类记录采用主键和JSON负载，接口校验控制语义，没有全量迁移原数据库。
